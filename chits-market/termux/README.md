# Сервер Chits Market на Android через Termux

Да, телефон может хранить каталог и раздавать APK. Для этого используется готовый Python-сервер проекта без платного хостинга и Firebase. Сценарии ниже запускают его **только на этом же телефоне**: это подходит для входа администратора, загрузки APK и работы маркета на одном Android-устройстве.

Пока процесс Termux запущен, сервер работает. Android может остановить его при нехватке памяти, энергосбережении, закрытии Termux или перезагрузке. Это не гарантированный круглосуточный хостинг. Сам Chits Market продолжит устанавливать ранее сохранённые APK и работать с подготовленной офлайн-моделью даже после остановки сервера.

## Установка

Установите актуальный Termux из поддерживаемого официального источника: [F-Droid](https://f-droid.org/packages/com.termux/) или [официальные релизы проекта](https://github.com/termux/termux-app/releases). Не скачивайте случайные перепакованные APK. Затем в Termux:

```sh
pkg install git python
git clone --branch downloads/offline-games-v1 --single-branch https://github.com/nuralisalimov03-netizen/hhhhhg.git chits-market-repo
cd chits-market-repo/chits-market
bash termux/setup.sh
bash termux/start.sh
```

Если репозиторий уже скачан, используйте существующий каталог и обновите его обычным `git pull --ff-only`. Дополнительный worktree не нужен.

При первом `setup.sh` введите пароль для администратора **Leon_Salimov**. Ввод скрыт; пароль не записывается в исходники или историю команд. Можно выбрать тот же пароль, которым вы пользовались ранее. Сценарий сохраняет только PBKDF2-хеш. Повторный запуск `setup.sh` сохраняет администратора и его пароль, а те же встроенные игры не дублирует. Скрипт проверяет Python 3.12+ и устанавливает Python/Git через `pkg`, только если они отсутствуют.

Данные находятся в приватном каталоге Termux:

```text
~/.local/share/chits-market/
    market.sqlite3
    files/
```

Здесь находятся каталог, APK, хеш пароля и сессии администратора. Не размещайте этот каталог в GitHub, общей памяти Android, публичном ZIP или папке Firebase Hosting. Его можно переопределить переменной `CHITS_TERMUX_HOME`; это полный путь каталога данных. Для резервной копии остановите сервер и скопируйте весь каталог в защищённое место. Удаление Termux обычно удаляет его приватные данные.

## Подключение маркета на этом же телефоне

1. Оставьте `start.sh` работающим в Termux.
2. В Chits Market откройте «Настройки». Выключите режим Firebase, если он был включён.
3. В настройках своего сервера укажите `http://127.0.0.1:8765` и сохраните.
4. Войдите как `Leon_Salimov` с паролем первого запуска. Теперь можно публиковать APK в этот локальный каталог.

`127.0.0.1` обозначает **тот же телефон**, а не другой компьютер. HTTP разрешён нативным приложением только для loopback-адресов: пароль не проходит через Wi-Fi или Интернет. В браузере этого же телефона тот же локальный адрес открывает веб-интерфейс администратора.

В Android-приложении запросы к этому локальному API идут через ограниченный нативный HTTP-мост, чтобы не зависеть от разрешений Chromium Local Network Access для HTTPS-интерфейса. Мост допускает только известные маршруты маркета и локальные адреса, отклоняет перенаправления и не отключает CORS, TLS или защиту mixed content. Файл для публикации передаётся потоком из выбранного Android URI, без преобразования APK в base64.

Сервер уже добавляет «Орбиту» и «Прорыв» из файлов проекта. Новые APK публикуются через веб-интерфейс/маркет. Без Интернета можно обращаться к серверу на этом телефоне; для установки после остановки Termux сначала сохраните APK в «Загрузки» Chits Market.

Остановить сервер: **Ctrl+C** в Termux (при необходимости используйте дополнительную клавишу CTRL на панели Termux). Повторный запуск:

```sh
cd ~/chits-market-repo/chits-market
bash termux/start.sh
```

Повторный запуск при уже работающем сервере не создаёт второй экземпляр. Порт можно изменить: `bash termux/start.sh --port 8766`; затем измените его и в настройках маркета.

## Энергосбережение

При необходимости разрешите Termux работать в фоне в настройках Android и отключите для него оптимизацию батареи. Если команда доступна, можно вручную выполнить `termux-wake-lock` перед запуском и `termux-wake-unlock` после остановки. Wake lock увеличивает расход батареи и не защищает процесс от принудительного завершения Android. Не рассчитывайте, что процесс автоматически переживёт перезагрузку; в этой версии автозапуск Termux:Boot не настраивается.

## Другие телефоны и удалённый доступ

Текущие сценарии не открывают сервер в LAN: `start.sh` всегда привязывается к `127.0.0.1`. Адрес вида `http://192.168…` передаёт пароль по сети без шифрования; нативный Chits Market также отклоняет удалённый HTTP. Простая замена `127.0.0.1` на IP телефона не создаёт безопасный публичный маркет.

Для других устройств нужен **публичный HTTPS-адрес**. Один вариант — ваш собственный VPS с доменом и TLS reverse proxy. На телефоне можно явно открыть SSH reverse tunnel к своему серверу:

```sh
pkg install openssh
ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -R 127.0.0.1:18765:127.0.0.1:8765 YOUR_USER@YOUR_VPS_HOST
```

Команда не создаёт VPS, домен, аккаунт или ключ SSH. Используйте свой проверенный хост и его штатную аутентификацию. Порт `18765` остаётся loopback на VPS; настройте там HTTPS reverse proxy к `127.0.0.1:18765`, например Caddy:

```caddy
market.example.org {
    request_body {
        max_size 201MB
    }
    reverse_proxy 127.0.0.1:18765
}
```

Замените примеры собственными данными, настройте DNS и доступ SSH/TLS на VPS. На других телефонах укажите полученный HTTPS-домен. Работать должны и Termux-сервер, и SSH-соединение, и VPS. Если VPS нет, этот проект сам его не приобретает и не публикует магазин автоматически. Настройки сетевого обхода и отдельный VPN не требуются.

## Альтернатива Git: ZIP с проверкой

Если скачиваете исходники ZIP, сначала проверьте их по опубликованной SHA-256; не выполняйте `curl | bash`. Например, в отдельной пустой папке Termux:

```sh
pkg install curl unzip coreutils python
curl -fL https://raw.githubusercontent.com/nuralisalimov03-netizen/hhhhhg/downloads/offline-games-v1/Chits-Market-source.zip -o Chits-Market-source.zip
curl -fL https://raw.githubusercontent.com/nuralisalimov03-netizen/hhhhhg/downloads/offline-games-v1/Chits-Market-SHA256SUMS.txt -o Chits-Market-SHA256SUMS.txt
sha256sum -c --ignore-missing Chits-Market-SHA256SUMS.txt
unzip Chits-Market-source.zip
cd chits-market
bash termux/setup.sh
bash termux/start.sh
```

Продолжайте только если проверка **Chits-Market-source.zip: OK** прошла; при ошибке не запускайте архив. Проверка из одного источника обнаруживает повреждение передачи, но не заменяет доверие к владельцу репозитория. В ZIP присутствуют встроенные APK, поэтому отдельное скачивание «Орбиты» и «Прорыва» не нужно.

## Проверка разработки

```sh
python3 -m unittest discover -s termux -p 'test_*.py' -v
```

Интеграционный тест на Linux-хосте запускает настоящие `setup.sh`/`start.sh`, проверяет готовность API, скачивание и SHA-256 APK, повторную подготовку, защиту от второго экземпляра и сохранение администратора/каталога/сессии после перезапуска. Отдельные Java-тесты проверяют настоящий транспорт: вход, потоковую публикацию APK, каталог, удаление и выход, запрет внешних адресов/маршрутов/заголовков, перенаправлений и слишком больших ответов. Для Java-тестов нужны подготовленные Java/ECJ и закреплённый host-test `org.json` (как в остальных Java-проверках проекта); в самом Android эти классы предоставляет система.

`python3 tests/test_termux_webview.py` отдельно проверяет браузерный HTTPS→HTTP-loopback путь с обычным пользовательским разрешением Local Network Access. В Chromium 154 без этого разрешения запрос блокируется до сервера; нативный мост не зависит от такого разрешения. Это **не проверка на физическом Android с Termux**; её нужно выполнить на вашем телефоне.
