# Chits Market 1.2

Android-маркет с оригинальным чёрно-зелёным интерфейсом: крупные подборки, карточки, списки, отдельный поиск, плавные переходы и поддержка уменьшения движения. Нужны Android 8+ ARM64 и актуальный Android System WebView. Подпись сохранена: обновление устанавливается поверх 1.0/1.1.

## Что изменилось в ИИ

- **Быстрый текст** — отдельная Qwen2.5 0.5B Q4_K_M, ориентировочно 400 МБ. По умолчанию готовится только эта модель, а не большой визуальный профиль.
- **Фото** — отдельный режим Qwen2.5-VL 3B с проектором, ориентировочно 3–4 ГБ. Подготовка запускается явно; существующие загруженные веса сохраняются.
- Модель больше не читается и не создаётся заново перед каждым вопросом. Кэш учитывает канонический путь, размер, время изменения и режим; смена файла/режима и ошибки сбрасывают его.
- Ответ появляется по мере настоящей генерации токенов. Есть **«Остановить»**; частичный ответ сохраняется. Отмена не ждёт Java-монитор, CPU-декодирование прерывается через native callback; уже начатое кодирование фотографии завершается до безопасной точки отмены.
- По умолчанию ответы короче: до 96 токенов для текста и 128 для фото. Используется до четырёх доступных CPU-потоков. Это уменьшает работу, но фактическая скорость на конкретном телефоне пока не измерена.

Первый ответ после запуска или смены модели всё ещё требует загрузки весов в память. Если маленькая текстовая модель ещё не готова, но есть Qwen-VL, текст может временно использовать её без загрузки проектора; интерфейс показывает, что это резервный вариант. Веса на диске и в APK сами по себе не делают вычисления мгновенными.

## Честный статус весов в APK

**В опубликованном небольшом APK 1.2 реальных весов пока нет.** В облачной среде скачивание официального Hugging Face заблокировано (`HTTP 403`), а API GitHub для больших release-файлов также недоступен. Домены подготовлены в черновике сетевых настроек среды, но изменения ещё не применены. После применения нужно реально скачать проверенные веса и пересобрать отдельный большой APK; наличие упаковщика не означает, что эта сборка уже создана.

Добавлена настоящая поддержка встроенных моделей: локальные GGUF режутся на части по 64 МиБ, включаются в assets и распаковываются без Интернета в приватный каталог с проверкой размера/SHA-256 и нативной проверкой перед использованием. При первом запуске быстрого режима распаковывается только текстовая модель; встроенное зрение готовится отдельно по запросу. Существующие импортированные модели не перезаписываются. Интерфейс пишет «в APK» только при наличии соответствующего манифеста в самой сборке.

Подготовка большого варианта после открытия сети:

```sh
python3 tools/fetch-models.py --profile fast --output-dir /workspace/.chits-tools/models
```

Для всех моделей используйте `--profile full`. Загрузчик закрепляет неизменяемую ревизию официального репозитория, проверяет LFS SHA-256/размер/GGUF и продолжает `.part` после обрыва. Он сохранит `paths.json` и выведет точную команду `tools/bundle-models.py` с фактическими путями и ревизией. Затем:

```sh
# Выполните команду bundle-models.py, выведенную загрузчиком.
bash tools/build-apk.sh
```

Быстрый вариант станет размером в сотни мегабайт, полный — несколько гигабайт. Для установки потребуется место под APK и распакованные веса. Большие файлы не следует коммитить обычным Git: у GitHub есть ограничения размера Git-файла и отдельного Release asset. Пакетирование/установка полного многогигабайтного APK пока не проверены; при необходимости потребуется отдельное хранилище или разделение доставки. Сгенерированный `assets/models` исключён из Git и ZIP исходников.

В обычной небольшой сборке текстовая модель скачивается на телефон по Wi-Fi без тарификации. Ручная кнопка разрешает мобильную сеть. Существующий фото-профиль не удаляется; его подготовку/продолжение можно запустить отдельно. Приложение показывает прогресс и источник модели, сохраняя проверенные частичные файлы после обрыва.

## Сервер на телефоне через Termux

**Да, это поддерживается.** Телефон может хранить каталог и APK без Firebase и платного хостинга. [Полная инструкция Termux](termux/README.md).

В Termux:

```sh
pkg install git python
git clone --branch downloads/offline-games-v1 --single-branch https://github.com/nuralisalimov03-netizen/hhhhhg.git chits-market-repo
cd chits-market-repo/chits-market
bash termux/setup.sh
bash termux/start.sh
```

При первом запуске задайте пароль `Leon_Salimov` скрытым вводом. Повторная настройка сохраняет администратора и каталог. Данные — `~/.local/share/chits-market`; не публикуйте их. В Chits Market выключите Firebase и укажите `http://127.0.0.1:8765` как адрес своего сервера.

Новый Android native transport обращается к loopback напрямую, передаёт JSON и потоковый multipart APK и не зависит от разрешения Chromium на доступ к локальной сети. Адреса, маршруты и заголовки ограничены; произвольные внешние URL и перенаправления запрещены. Пароль/токен и APK не преобразуются в base64 и не пишутся в логи.

Так сервер доступен **на том же телефоне**. Для других устройств нужен отдельный HTTPS-доступ, например ваш VPS с TLS и явно настроенным SSH reverse tunnel. Сценарии не покупают хостинг, не открывают небезопасный LAN HTTP и не настраивают VPN. Android может остановить Termux при энергосбережении, закрытии или нехватке памяти; круглосуточная работа не гарантируется. Ранее сохранённые APK устанавливаются офлайн независимо от сервера.

## Отдельный TikTok

По уточнению пользователя TikTok **не входит в Chits Market**: карточка и переключатель регионов убраны из маркета. Запрошен отдельный настоящий TikTok с аккаунтом, лентой и сменой региона, не имитация интерфейса и не WebView-обёртка.

Отдельный APK пока не собран: подлинный исходный TikTok APK и проверенный совместимый набор патчей не предоставлены. Исследованный официальный ReVanced CLI доступен, но репозиторий его патчей заблокирован GitHub; поддерживаемое текущее дерево Morphe не содержит TikTok/SIM-патчей. Неизвестные модификации и обход проверок подписи/provenance не использовались. Для продолжения нужна достоверная совместимая основа/сборка; пароль и токены TikTok для сборки не нужны.

Работа в России не подтверждена и не гарантируется. Вход в аккаунт должен выполняться пользователем только на телефоне.

## Фото и приватность

Фото выбирается системным файловым менеджером, исправляется ориентация, удаляется EXIF, длинная сторона уменьшается до 560 пикселей. Подготовленная копия находится в приватном кэше; её можно убрать, при холодном запуске вложение сбрасывается. Изображения не сохраняются в localStorage или истории и не отправляются в Firebase/на сервер. В истории остаются текст и название вложения.

Для фото нужны оба совместимых файла Qwen-VL одной ревизии. Модель может ошибаться, плохо читать мелкий текст и отвечать медленно. Vision-контекст — 4096 токенов, текстовый — 2048. Текущий запрос получает текущую фотографию, а не всю прошлую историю. Небольшие модели существенно слабее ChatGPT.

## Firebase и установка приложений

Firebase Hosting/Auth/Firestore/Storage и защищённые правила сохранены: [инструкция](firebase/README.md). Настоящий Firebase-проект пока не предоставлен/не развёрнут. Для Storage нужен Blaze с платёжным аккаунтом. Публичный config можно вставить в настройках без пересборки APK; пароль и service-account ключи туда не вводят. Администратор требует серверный custom claim `chitsAdmin: true`; локальный Python-аккаунт не переносится автоматически.

«Орбита» и «Прорыв» уже включены. Сохранённые или импортированные APK устанавливаются без Интернета через системное подтверждение Android. Другие приложения сначала нужно скачать с подключённого сервера. Удаление сохранённого APK не удаляет установленное приложение. Маркет не обходит проверку подписи и разрешения Android и не выполняет антивирусный анализ.

## Сборка и проверки

```sh
bash tools/build-apk.sh
python3 tools/package-release.py
```

Linux x86_64, Python 3.12+, Java 21, curl/unzip/zip/openssl/keytool; Gradle не нужен. Инструменты с проверяемыми суммами хранятся в `/workspace/.chits-tools`, приватный ключ обновлений — `/workspace/.chits-signing`. Сохраните его приватно; он не входит в Git или исходный ZIP. Для C++ сначала `bash ai-native/build.sh`, затем сборка APK. Подробности и лицензии — [ai-native](ai-native/README.md).

```sh
python3 -m unittest discover -s server -v
python3 tests/test_ui.py
python3 tests/test_model_downloader.py
python3 tests/test_vision_manifest.py
python3 tests/test_bundle_models.py
python3 tests/test_fetch_models.py
python3 -m unittest discover -s termux -p 'test_*.py' -v
bash ai-native/tests/run_cache_test.sh
```

Выполнены сборка/проверка подписи, 11 браузерных тестов, реальный Java HTTP/TLS-загрузчик, тесты манифеста/упаковки/получения весов, Termux launcher/Java HTTP transport, Java JNI lifecycle и два C++ host-теста декодирования/UTF-8/отмены. Fixtures упаковщика не являются настоящими весами. Firebase в UI использует HTTP mocks. Реальные веса/скорость/установка на Android и реальный Termux на телефоне пока не проверены.

Правила Firebase проверяются `cd firebase && npm ci && npm test`; прежняя попытка загрузить эмулятор блокировалась `storage.googleapis.com` (CONNECT 403). Доступ добавлен в черновик среды, но не применён. Firebase provisioning unit-тесты ранее прошли; живой облачный проект не опубликован. Проверки не заменяют тестирование на устройстве и после реального развёртывания.
