# Chits Market 1.1

Android-маркет с анимациями, локальными APK, Firebase-каталогом и настоящим офлайн-ИИ, который принимает текст и фотографии. Нужны Android 8.0+ ARM64, современный Android System WebView и достаточно свободного места для модели. APK подписан тем же ключом, что версия 1.0: устанавливайте обновление поверх неё.

## Сначала на телефоне

1. Установите `dist/Chits-Market.apk`. «Орбита» и «Прорыв» уже включены — их APK доступны для установки без Интернета через системное подтверждение Android.
2. Подключитесь к Wi-Fi без тарификации. **Qwen2.5-VL 3B и компонент зрения начнут загружаться автоматически.** Вместе это ориентировочно 3–4 ГБ; приложение покажет фактический размер из метаданных. Оставьте приложение открытым. При потере сети часть файлов сохраняется, загрузка продолжится при следующем запуске/подключении; перед использованием сверяются размеры и SHA-256.
3. Мобильная сеть разрешается только ручной кнопкой в «Помощнике». Если Wi-Fi отмечен на телефоне как сеть с тарификацией, автоматический режим также будет ждать.
4. После подготовки модели откройте «Помощник», прикрепите фото и напишите вопрос. **Фото и вопросы не отправляются ни в Firebase, ни на сервер.** Интернет для ответов не нужен.

Для телефона с 8 ГБ ОЗУ выбран небольшой Qwen-VL, но успешная загрузка и скорость зависят от свободной памяти и конкретного устройства; на вашем телефоне это ещё нужно проверить. Система может остановить приложение в фоне; частично скачанные веса сохраняются. Нужны как минимум размер оставшихся файлов и запас 256 МБ на диске, а при обновлении профиля — место для старых и новых файлов.

## Фото и ИИ

Работает реальный ARM64 CPU-движок llama.cpp с `mtmd`: изображение кодируется визуальной моделью, затем ответ генерируется локально. Профиль `ggml-org/Qwen2.5-VL-3B-Instruct-GGUF` поддерживается закреплённой версией upstream. Языковая часть Q4_K_M и проектор Q8_0/F16 закрепляются на одной неизменяемой ревизии; название и размер файлов берутся из фактических HTTPS-метаданных.

Фотография выбирается через системный файловый менеджер, исправляется ориентация, удаляются EXIF-метаданные и уменьшается длинная сторона до 560 пикселей для экономии памяти. Исходник не сохраняется; подготовленная копия находится в приватном кэше приложения. Её можно убрать кнопкой, при холодном запуске вложение сбрасывается. Изображения и base64 не записываются в историю или localStorage; в истории остаются текст и название вложения.

Это существенно слабее ChatGPT: ответы могут быть ошибочными и медленными, мелкие детали и текст на фото могут не распознаться. Vision-контекст — 4096 токенов, ответы — до 256 токенов. История показывается и хранится только локально, но модель получает текущий вопрос с текущей фотографией, а не весь прежний диалог. Кнопки быстрой справки помечены как обычная справка.

Прежняя текстовая модель `assistant.gguf` сохраняется при обновлении. До завершения загрузки нового профиля с ней можно задавать текстовые вопросы. Импорт одной текстовой GGUF-модели не добавляет понимание фотографий.

**На настоящем Android загрузка всех весов и семантическое понимание фотографий ещё не проверены.** Успешно собраны ARM64 JNI и APK, проверены декодирование изображений, загрузка/продолжение файлов и интерфейс. Эти проверки не заменяют запуск на телефоне.

## Firebase вместо собственного сервера

Готовы Firebase Hosting, Authentication, Firestore и Storage: каталог и APK доступны пользователям, публикация/удаление разрешены только администратору с custom claim `chitsAdmin: true`. Никнейм в маркете — **Leon_Salimov**, а для Firebase Authentication выбирается email администратора.

**Настоящий проект пока не подключён и не опубликован:** пользователь ещё создаёт Firebase-проект. По умолчанию публичная конфигурация пуста и Firebase выключен. Полная [инструкция создания проекта, администратора и публикации](firebase/README.md) находится в `firebase/`.

В Android откройте «Настройки» → Firebase и вставьте публичный JSON с `apiKey`, `projectId`, `authDomain`, `storageBucket`, `appId` и `adminEmail`. После создания проекта это можно сделать **без пересборки APK**. Пароль, приватный ключ service account и токены в этот JSON не вставляют. Публичный apiKey не даёт прав администратора; их проверяют серверные правила. Для браузерной версии заполните `app/src/main/assets/web/firebase-config.js` перед публикацией Hosting.

Для хранения APK в Cloud Storage for Firebase нужен **Blaze с платёжным аккаунтом**; расходы зависят от использования. Оплата, бакет и реальные ресурсы автоматически не создавались. Правила по умолчанию не разрешают публичную запись. Старый Python API остаётся резервным вариантом, [его инструкция](server/README.md) сохранена. Его локальный администратор не переносится в Firebase автоматически.

Уже сохранённые APK устанавливаются без сети независимо от Firebase. Новые приложения сначала нужно скачать. Android всегда запрашивает системные разрешения и подтверждение установки; маркет их не обходит.

## Сборка

Нужны Linux x86_64, Python 3.12+, Java 21, curl, unzip, zip, openssl и keytool. Gradle и внешние JS-зависимости для APK не нужны.

```sh
cd /workspace/hhhhhg/chits-market
bash tools/build-apk.sh
```

SDK 35 / Build Tools 35.0.0 и ECJ скачиваются с официальных источников с проверкой закреплённых сумм. Кэш инструментов — `/workspace/.chits-tools` (`CHITS_TOOLS_DIR`). Приватный ключ подписи — `/workspace/.chits-signing` (`CHITS_SIGNING_DIR`); сохраните его приватно для дальнейших обновлений. Ключ и пароль не входят в исходники и публичные архивы.

После изменений C++ сначала выполните `bash ai-native/build.sh`, затем повторите сборку APK. Используется закреплённый llama.cpp b6500, Android NDK r27d и baseline ARMv8-A с 16-КиБ выравниванием. Лицензии llama.cpp, stb_image и miniaudio включены в APK. Подробности — [ai-native/README.md](ai-native/README.md).

## Проверки

```sh
python3 -m unittest discover -s server -v
python3 tests/test_ui.py
python3 tests/test_model_downloader.py
python3 tests/test_vision_manifest.py
cd firebase
npm ci
npm run test:provision
npm test
```

Браузерные проверки требуют установленных Playwright и Chromium, файловые — ECJ и Java. Они используют временные loopback-серверы и тестовые данные. В облачной среде выполнены 7 API-тестов, 7 браузерных тестов с mock Android/Firebase, 14 реальных Java HTTP/TLS-тестов загрузчика, 12 тестов манифеста и 4 теста provisioning. Отдельный C++ host-тест реального декодера/масштабирования изображений прошёл; команда приведена в документации `ai-native`.

**Firebase rules emulator suite пока не запускался:** прокси облачной среды отклонил загрузку официального эмулятора с `storage.googleapis.com` (CONNECT 403). Домен добавлен в черновик настроек среды; после применения сетевого изменения можно запустить `npm test`. Реальные сервисы и безопасность живого проекта также должны быть проверены после авторизованной публикации.
