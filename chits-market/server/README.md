# Сервер Chits Market

Сервер хранит каталог, APK и администратора. Зависимости: Python 3.12+ и стандартная библиотека. У приложения нет общего встроенного пароля: сервер хранит PBKDF2-хеш, а не пароль. Никнейм первого администратора по умолчанию — `Leon_Salimov`.

## Первый запуск

Из каталога `chits-market` создайте постоянный каталог данных вне исходников, например `/var/lib/chits-market`. На локальной машине можно использовать `./.local-data` (не публикуйте его в Git).

```sh
python3 server/app.py init --data-dir /var/lib/chits-market --password-stdin
```

Введите пароль администратора в stdin. Для автоматического запуска вместо stdin можно передать путь к защищённому файлу через `--password-file PATH` или переменную `CHITS_ADMIN_PASSWORD`. Значение пароля не указывайте в командной строке, исходниках или Dockerfile. Повторный `init` не меняет существующего администратора.

В исходном облачном окружении администратор уже подготовлен в отдельном каталоге данных; этот каталог содержит конфиденциальные данные и не входит в распространяемый ZIP исходников.

```sh
python3 server/app.py seed --data-dir /var/lib/chits-market --repo /workspace/hhhhhg
python3 server/app.py serve --data-dir /var/lib/chits-market --host 127.0.0.1 --port 8765
```

`seed` добавляет существующие `Orbita-v6.apk` и `Breach-v2.apk`; при повторном запуске те же контрольные суммы пропускаются. `seed` необязателен, если хотите пустой каталог.

Проверка: `GET /health` возвращает `status: ok` и `adminConfigured: true`; `GET /api/apps` — каталог. По корневому адресу `/` сервер также открывает веб-интерфейс маркета: через его настройки администратор может войти и загрузить APK с компьютера. В приложении откройте настройки и укажите **HTTPS-адрес вашего сервера**. На телефоне `localhost` обозначает телефон, а не сервер. Веб-файлы по умолчанию читаются из `app/src/main/assets/web`; можно указать `--web-dir PATH` или `CHITS_WEB_DIR`.

## Удалённый доступ

Для удалённых загрузок нужен ваш VPS/другой постоянно работающий хост и домен. Этот проект не создаёт хостинг и не публикует сервер автоматически. Разверните API за HTTPS reverse proxy, например Caddy. Пример `Caddyfile`:

```caddy
market.example.org {
    request_body {
        max_size 201MB
    }
    reverse_proxy 127.0.0.1:8765
}
```

Замените домен своим, настройте его DNS и держите API под менеджером процессов. Пример для запуска вручную приведён выше; процесс должен запускаться после перезагрузки хоста. Не отправляйте пароль по обычному HTTP. HTTP-сервер на Python предназначен для работы за reverse proxy, а не для прямой публикации в Интернет.

Можно запустить API в Docker:

```sh
docker build -f server/Dockerfile -t chits-market-api .
docker run --rm -it -v chits-data:/data chits-market-api init --data-dir /data --password-stdin
docker run -d --restart unless-stopped --name chits-market-api \
  -p 127.0.0.1:8765:8765 -v chits-data:/data chits-market-api \
  serve --data-dir /data --host 0.0.0.0 --port 8765
```

Порт Docker привязан к loopback хоста; HTTPS завершает reverse proxy. Сохраняйте резервные копии **всего каталога данных** (SQLite и `files/`). Во время копирования остановите API или используйте штатный SQLite backup и согласованную копию APK. База содержит хеш пароля и сессии; не публикуйте её.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/health` | Проверка готовности |
| GET | `/api/apps` | Каталог `{apps: [...]}` |
| POST | `/api/auth/login` | JSON `{username,password}` → `{token,username,expiresIn}` |
| POST | `/api/auth/logout` | Завершить текущую сессию |
| POST | `/api/apps` | Multipart: `title`, `description`, `category`, `file` |
| DELETE | `/api/apps/{id}` | Удалить приложение и APK |
| GET | `/files/{id}.apk` | Скачать неизменяемый APK |

Для загрузки, удаления и выхода нужен `Authorization: Bearer TOKEN`. Сессия действует 24 часа. Пять неудачных входов для одной пары IP/никнейм ограничивают повторные попытки на 15 минут. Пароль и токен не передаются в URL. Multipart ограничен APK размером 200 МБ; сохраняются временные файлы на диске, а не весь APK в памяти. Проверяются структура ZIP, CRC, манифест и `classes.dex`; это **не антивирусная проверка**. Android самостоятельно проверяет подпись при установке. Пакет и версия берутся из манифеста APK.

Для WebView с локальным origin CORS по умолчанию разрешает `*`, без cookie и `Access-Control-Allow-Credentials`; изменение каталога всё равно требует Bearer-токен. При использовании только браузерного клиента можно ограничить origin: `--cors-origin https://your-frontend.example`.

Загруженный каталог доступен при соединении с сервером. Без Интернета устанавливаются только APK, заранее сохранённые в приложении или импортированные из локального файла. Удаление APK с сервера не удаляет уже скачанную копию на телефоне.

## Проверка

```sh
cd server
python3 -m unittest -v test_server.py
```

Тесты поднимают временный API на loopback, проверяют вход/отказ, выход, запрет неавторизованной и повреждённой загрузки, публикацию настоящего APK, скачивание по SHA-256, сохранность SQLite при повторном открытии и удаление. Для запуска тестов требуется разрешение локальных сокетов. Исходные APK не изменяются.
