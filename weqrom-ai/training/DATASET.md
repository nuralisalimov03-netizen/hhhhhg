# Набор данных Chits / Weqrom AI

Текущий выпуск 1.1 продолжает исходные веса на `curriculum_v2.py`; описание исходного корпуса 1.0 сохранено ниже. Новый набор содержит 16 000 обучающих, 1000 проверочных и 100 итоговых записей. Он генерируется из собственных шаблонов без внешних датасетов, готовых весов или API для сбора ответов; помощь ИИ при написании шаблонов явно указана в метаданных.

В исходном наборе часть ответов кода зависела от случайных параметров, не заданных вопросом. В V2 изменяемые параметры всегда указаны либо имеют фиксированное правило. Добавлены короткое извлечение/копирование и многошаговые диалоги. В режиме `--objective supervised` модель видит диалог целиком, без разрезания вопроса случайным окном; цели — только содержимое ответов и EOS. Дополнение справа и входные сообщения не участвуют в функции потерь. Слишком длинная запись отклоняется вместо скрытого обрезания.

Разделы V2 используют отдельные семейства вопросов и заранее разделённые наборы параметров. Пары чисел итогового теста исключены из V1 и V2 обучения; исходные проверочные пары, тройки линейных уравнений и точные вопросы исключены из V2 обучения. Значения копирования, цепочки памяти и комбинации параметров кода также разделены между частями V2 до генерации. При этом две итоговые тройки линейных уравнений и один набор параметров счётчика встречались в исходном обучении V1. Это ограничение явно раскрыто в сравнении; вся итоговая сотня не считается невиданной по параметрам во всей цепочке. Знакомые ответы о фактах могут повторяться при разных формулировках: это проверка переноса, не открытия новых знаний.

`test.jsonl` и `TEST_LOCK.json` заморожены до продолжения обучения. Генератор отказывается заменять существующий итоговый тест другими байтами; повторный запуск с теми же байтами не меняет сам файл. Выбор checkpoint использует только validation. Хеш итогового теста: `573849f41748c95d75e5ab17c9f468f3cc2ca3b174c79884b514b03e12099cc7`. После просмотра результатов дальнейшие эксперименты требуют нового независимого теста.

Итоговые 100 заданий: 20 копирований, 10 связанных диалогов, 20 примеров кода, 20 знакомых ответов, 20 арифметических задач и 10 линейных уравнений. Арифметический раздел этого небольшого теста не содержит деления. Полные задания, ответы моделей и ошибки сохранены в [отчётах сравнения](../reports/v11-comparison.json); [метаданные V2](../reports/curriculum-v2.json). 13 тестов генератора проверяют воспроизводимость, разделение и все параметры; они не заменяют измерения ответов модели.

## Исходный корпус 1.0

`corpus.py` создаёт собственный синтетический учебный набор на русском языке. Шаблоны проекта написаны с помощью ИИ-ассистента в этой сессии; арифметические примеры, линейные уравнения и варианты кода создаются детерминированными генераторами. Генератор не скачивает чужие наборы данных и не вызывает внешние API моделей. Предобученные веса и токенизаторы не используются. Это происхождение отражено в `meta.json`: `templates_authored_with_ai_assistance: true`, `external_model_api_inference: false`, `downloaded_datasets: []`.

Это небольшой набор для экспериментального обучения модели с нуля. Хороший результат на этих примерах не доказывает способность свободно отвечать на любые вопросы, понимать фотографии или надёжно писать программы. Повторяющиеся конструкции упрощают обучение и ограничивают разнообразие ответов. Тексты следует проверить перед расширением обучения.

## Создание и формат

Публичный Python API:

```python
from pathlib import Path
from corpus import build_corpus, format_chatml, write_corpus

train, validation, meta = build_corpus(
    seed=20261104, train_size=16000, validation_size=1200
)
meta = write_corpus(
    Path("data/generated"),
    seed=20261104, train_size=16000, validation_size=1200,
)
```

Одинаковые параметры дают одинаковые примеры и порядок. По умолчанию создаётся 16 000 обучающих и 1 200 проверочных примеров. Небольшой размер можно выбрать для проверки кода, например 600 и 100. Файлы `train.jsonl` и `validation.jsonl` содержат по одному JSON-объекту на строку; `meta.json` хранит параметры, происхождение, описание разделения и SHA-256, размеры и число примеров в выходных файлах.

Каждая запись имеет поля:

| Поле | Значение |
| --- | --- |
| `id` | Уникальный идентификатор примера. |
| `split` | `train` или `validation`. |
| `category` | Раздел набора: например, арифметика или основы HTML/JavaScript. |
| `family` | Идентификатор семейства формулировок. |
| `messages` | Вопрос `user` и ответ `assistant` с непустым `content`. |
| `task` | Метаданные задачи для проверки ответа. |

Для арифметики `task` содержит `kind: "arithmetic"`, `operation` (`add`, `subtract`, `multiply`, `divide`), два целочисленных `operands` и целочисленный `result`. Деление подбирается без остатка. Для линейного уравнения `kind: "linear"`, `operands: [a, b, x]`, `rhs: c`, `result: x` описывают равенство `a*x + b = c`, где `a != 0`. Для авторских ответов `kind: "authored"` и `topic` описывают тему. Примеры кода имеют `kind: "code"`, `topic` (`card`, `counter` или `function`), а также параметры `initial` и `step`.

`format_chatml(example)` возвращает текст диалога:

```text
<|im_start|>user
ВОПРОС<|im_end|>
<|im_start|>assistant
ОТВЕТ<|im_end|>
```

Системное сообщение в корпус не добавляется. Обучение и приложение должны использовать одинаковый формат, словарь и идентификаторы специальных токенов. Проверочную выборку нельзя добавлять в обучение токенизатора или модели.

## Содержание и разделение

Набор включает короткие диалоги, вычисления с объяснением, линейные уравнения, базовые математические понятия, объяснения HTML и JavaScript, простые рекомендации и ответы о возможностях и ограничениях помощника. Он не заменяет широкий корпус русского языка и программного кода.

Обучающая и проверочная выборки создаются раздельно:

- точные вопросы и идентификаторы не повторяются между выборками;
- семейства формулировок проверочной выборки целиком исключены из обучения;
- пары арифметических операндов не пересекаются между выборками, включая перестановку чисел и другую операцию;
- параметры линейных задач разделены между выборками.

Такое разделение позволяет проверить перенос на другие числа и формулировки внутри синтетических задач. При этом обе выборки написаны одним генератором, поэтому они могут разделять стиль, темы и структуру рассуждений. Отдельная ручная проверка на независимых вопросах остаётся необходимой. Проверочные примеры нельзя использовать для корректировки ответов или повторно включать в обучение.

## Проверка

```bash
python3 -m unittest discover -s weqrom-ai/training -p 'test_corpus.py'
```

Тесты проверяют воспроизводимость, структуру сообщений, отсутствие пересечений, вычисленные ответы и уравнения, формат ChatML, чтение JSONL и целостность записанных файлов. Это проверка генератора данных; качество обученной модели ею не измеряется.
